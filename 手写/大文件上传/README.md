# 大文件分片上传 - 五阶段实现

从最简单的整文件上传，逐步演进到生产级分片上传。每一阶段在前一阶段基础上迭代。

## 目录结构

```
大文件上传/
├── 第1阶段/   整文件上传（基线）
├── 第2阶段/   基础分片上传
├── 第3阶段/   hash 唯一标识 + 秒传 + 断点续传
├── 第4阶段/   Web Worker 算 hash + 抽样 hash
└── 第5阶段/   并发控制 + 失败重试 + 字节级进度
```

## 各阶段对比

| 阶段 | 解决的问题 | 引入的新概念 |
|---|---|---|
| 1 | 跑通链路 | FormData / multer |
| 2 | 大文件不爆内存、可分批 | `File.slice` / 临时目录 / 合并 |
| 3 | 唯一标识、秒传、断点续传 | 内容 hash / verify 接口 |
| 4 | hash 不阻塞主线程 / 提速 | Web Worker / 抽样 hash |
| 5 | 带宽利用率 / 抗抖动 / 真实进度 | 并发池 / 重试退避 / XHR 进度 |

## 启动方式（每个阶段都一样）

```bash
cd 第N阶段/server
pnpm install
pnpm dev
```

前端直接用浏览器打开 `第N阶段/client/index.html`，或用 VSCode Live Server 起静态服务。

## 后续可继续优化的方向

- 慢启动：根据网速动态调整 `CHUNK_SIZE` 和并发数
- 暂停/取消：用 `AbortController` 控制 fetch / xhr.abort()
- 合并阶段：流式合并避免占用文件句柄
- 分片完整性：每个分片单独算 md5，合并时校验
- 鉴权 + 限流：token、IP 限流、磁盘配额
